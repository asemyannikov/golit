В языке Go сигнатура функции позволяет задавать имена для возвращаемых значений. С технической точки зрения, именованные возвращаемые значения трактуются компилятором как локальные переменные, объявленные и инициализированные нулевыми значениями (zero values) в самом начале выполнения функции.

```go
func split(sum int) (x, y int) {
    // На этом этапе x = 0, y = 0
    x = sum * 4 / 9
    y = sum - x
    return // Эквивалентно return x, y
}
```

#### 1. «Голый» возврат (Naked Return)
Инструкция `return` без аргументов в функции с именованными возвращаемыми значениями называется «голым» возвратом. Она автоматически возвращает текущие значения именованных переменных.

Хотя это выглядит элегантно и экономит место, официальное руководство **Effective Go** дает строгую рекомендацию: *«Голые возвраты отлично подходят для коротких функций, но в длинных функциях они вредят читаемости»*.

**Почему это важно:**
В функции объемом 50+ строк разработчику, читающему код, придется прокручивать файл до самого верха, чтобы понять, что именно возвращает `return`. Явный возврат делает код самодокументируемым.

```go
// Плохо: в длинной функции неочевидно, что возвращается
func processLargeData(data []byte) (result []byte, err error) {
    // ... 40 строк сложной логики ...
    return // Что здесь возвращается? result? err? Обе переменные?
}

// Хорошо: намерения автора очевидны
func processLargeData(data []byte) ([]byte, error) {
    // ... 40 строк сложной логики ...
    return processedData, nil
}
```

#### 2. Синергия с `defer`: модификация результатов
Самая мощная особенность именованных возвращаемых значений раскрывается при использовании конструкции `defer`. Отложенная функция выполняется *после* того, как оператор `return` вычислит возвращаемые значения, но *до* того, как функция фактически вернет управление вызывающей стороне.

Если возвращаемые значения именованы, `defer` получает к ним доступ и может их изменить. Это стандартный паттерн для сквозного логирования, метрик и **оборачивания ошибок (error wrapping)**.

```go
func fetchUser(id int) (user *User, err error) {
    // Отложенная функция модифицирует именованную переменную err
    defer func() {
        if err != nil {
            // Добавляем контекст к ошибке перед тем, как она покинет функцию
            err = fmt.Errorf("fetchUser(id=%d): %w", id, err)
        }
    }()

    if id <= 0 {
        return nil, errors.New("невалидный идентификатор") 
        // Сработает defer, обернет ошибку, и вызывающий код получит:
        // "fetchUser(id=0): невалидный идентификатор"
    }
    
    // Логика получения пользователя...
    return &User{ID: id}, nil
}
```

#### 3. Подводный камень: затенение имен (Shadowing)
Поскольку именованные возвращаемые значения являются локальными переменными, они подчиняются строгим правилам области видимости Go. 

**Правило 1: Конфликт с аргументами**
Вы не можете использовать одно и то же имя для аргумента функции и её возвращаемого значения. Компилятор выдаст ошибку `redeclared in this block`.
```go
// Ошибка компиляции: x redeclared in this block
func calculate(x int) (x int) { 
    return x * 2 
}
```

**Правило 2: Локальное затенение**
Если вы объявите внутри функции локальную переменную с тем же именем, что и возвращаемое значение, вы «затените» (shadow) возвращаемую переменную. В этом случае «голый» возврат вернет значение *оригинальной* (внешней) переменной, а не той, которую вы меняли внутри блока.
```go
func shadowExample() (result int) {
    result = 10
    if true {
        result := 20 // Создана НОВАЯ локальная переменная, затеняющая result
        fmt.Println(result) // Выведет 20
    }
    return // Вернет 10, так как внешний result не был изменен!
}
```

#### 4. Использование пустого идентификатора `_`
Иногда вам не нужно имя для первого возвращаемого значения, но критически важно именовать ошибку для использования в `defer`. В таких случаях применяется пустой идентификатор `_`.

```go
func readConfig(path string) (_ *Config, err error) {
    defer func() {
        if err != nil {
            fmt.Printf("Не удалось прочитать конфиг из %s: %v\n", path, err)
        }
    }()
    // ... логика чтения ...
}
```

2. **Читаемость кода:** Почему использование «голого» возврата (naked return) считается антипаттерном в функциях, превышающих 10-15 строк кода?
3. **Взаимодействие с `defer`:** В какой последовательности выполняются следующие действия: вычисление аргументов `return`, выполнение `defer`-функций и фактический выход из функции?

#### Упражнение 1: Предсказать вывод
Проанализируйте код ниже. Что именно будет выведено в консоль и какое значение вернет функция?
```go
func tricky() (val int) {
    val = 1
    defer func() {
        val += 10
    }()
    
    if true {
        val := 5
        defer func() {
            val += 100
        }()
    }
    return
}

func main() {
    fmt.Println(tricky())
}
```

#### Упражнение 2: Рефакторинг (Читаемость)
Перепишите следующую функцию, избавившись от «голого» возврата и сделав её максимально понятной для других разработчиков, сохранив при этом именованные возвращаемые значения (так как они нужны для `defer`).
```go
func authenticate(token string) (user *User, err error) {
    defer func() {
        if err != nil {
            log.Printf("Auth failed: %v", err)
        }
    }()

    if token == "" {
        err = errors.New("empty token")
        return
    }
    
    u, e := db.FindUser(token)
    if e != nil {
        err = e
        return
    }
    
    user = u
    return
}
```
