В языке Go функции являются **объектами первого класса** (first-class citizens). Это означает, что они обладают теми же правами, что и любые другие значения: их можно присваивать переменным, передавать в качестве аргументов в другие функции, возвращать из функций и сохранять в структурах данных.

**Анонимная функция** – это функция, определенная без имени. Она объявляется буквально «на лету» и часто используется там, где требуется одноразовая логика.

**Замыкание (closure)** – это особый вид анонимной функции, которая «захватывает» (captures) переменные из окружающей её области видимости, даже после того как внешняя функция завершила своё выполнение.

```go
func counter() func() int {
    count := 0 // Эта переменная будет "захвачена" замыканием
    return func() int {
        count++
        return count
    }
}

func main() {
    c := counter()
    fmt.Println(c()) // 1
    fmt.Println(c()) // 2
    fmt.Println(c()) // 3
    
    // Каждый вызов counter() создает НОВОЕ независимое замыкание
    d := counter()
    fmt.Println(d()) // 1 (свой собственный счетчик)
}
```

#### 1. Механизм захвата переменных

Критически важно понимать: **замыкания захватывают переменные по ссылке, а не по значению**. Это означает, что все замыкания, созданные в одной области видимости, разделяют одни и те же переменные. Изменение переменной в одном месте отразится на всех замыканиях, которые её захватили.

```go
func sharedState() []func() int {
    x := 0
    fns := make([]func() int, 3)
    for i := 0; i < 3; i++ {
        fns[i] = func() int {
            x++ // Все три функции работают с ОДНОЙ переменной x
            return x
        }
    }
    return fns
}

func main() {
    funcs := sharedState()
    fmt.Println(funcs[0]()) // 1
    fmt.Println(funcs[1]()) // 2 (НЕ 1!)
    fmt.Println(funcs[2]()) // 3 (НЕ 1!)
}
```

#### 2. Классический подводный камень: замыкания в циклах (for)

До версии **Go 1.22** самым распространенным источником ошибок в Go было использование замыканий внутри цикла `for`. Переменная итерации (например, `i`) переиспользовалась на каждой итерации, и все замыкания захватывали одну и ту же ячейку памяти. В результате, когда замыкания выполнялись позже (например, в горутинах), они видели финальное значение переменной, а не значение на момент создания замыкания.

**Старое поведение (Go до 1.22):**
```go
// Все горутины выведут "5" или одно и то же число!
for i := 0; i < 5; i++ {
    go func() {
        fmt.Println(i) // Захватывает ОДНУ переменную i
    }()
}
```

**Решение (работает во всех версиях Go):**
Создание локальной копии через параметры анонимной функции. При таком подходе значение передается по значению в момент создания горутины.

```go
// Корректное поведение: выведет 0, 1, 2, 3, 4 (в произвольном порядке)
for i := 0; i < 5; i++ {
    go func(n int) {
        fmt.Println(n) // n – локальная копия
    }(i)
}
```

**Важное обновление Go 1.22:** Начиная с этой версии, семантика цикла `for` была изменена. Теперь на каждой итерации создается **новая** переменная, что устранило эту классическую ошибку. Однако понимание старого поведения остается обязательным для работы с унаследованным кодом и библиотеками, написанными для более ранних версий Go.

#### 3. IIFE (Immediately Invoked Function Expression)

Анонимные функции могут быть немедленно вызваны сразу после их объявления. Этот паттерн, пришедший из JavaScript, известен как IIFE и полезен для создания изолированной области видимости без загрязнения основного пространства имен.

```go
func processData() {
    result := func() int {
        // Вся сложная логика изолирована здесь
        temp := 100
        // ... вычисления ...
        return temp * 2
    }() // Немедленный вызов
    
    fmt.Println(result)
    // temp здесь недоступна
}
```

IIFE особенно полезен в сочетании с `defer`, когда необходимо инкапсулировать логику очистки ресурсов в рамках одной итерации цикла:

```go
func processFiles(files []string) {
    for _, file := range files {
        func() {
            f, err := os.Open(file)
            if err != nil { return }
            defer f.Close() // Закроется в конце этой анонимной функции
            // Работа с файлом
        }()
    }
}
```

#### 4. Практические паттерны использования

**А. Фабрика функций (Function Factory)**
Замыкания позволяют создавать функции-генераторы, которые порождают специализированные функции с предустановленной конфигурацией.

```go
func multiplier(factor int) func(int) int {
    return func(x int) int {
        return x * factor
    }
}

double := multiplier(2)
triple := multiplier(3)
fmt.Println(double(5)) // 10
fmt.Println(triple(5)) // 15
```

**Б. Инкапсуляция состояния (приватные переменные)**
Замыкания позволяют эмулировать приватные поля, недоступные извне. Это один из способов реализовать паттерн «модуль» в Go.

```go
func NewBankAccount(initial int) (deposit, withdraw, balance func() int) {
    money := initial
    
    deposit = func() int {
        money += 100
        return money
    }
    
    withdraw = func() int {
        if money >= 50 {
            money -= 50
        }
        return money
    }
    
    balance = func() int { return money }
    return
}
```

**В. Мемоизация (кэширование результатов)**
Замыкание идеально подходит для хранения кэша между вызовами функции.

```go
func memoizedFibonacci() func(int) int {
    cache := make(map[int]int)
    
    var fib func(int) int
    fib = func(n int) int {
        if n < 2 { return n }
        if val, ok := cache[n]; ok {
            return val
        }
        result := fib(n-1) + fib(n-2)
        cache[n] = result
        return result
    }
    return fib
}
```

**Г. Генераторы последовательностей**
Замыкания позволяют создавать функции-генераторы, которые выдают следующее значение при каждом вызове.

```go
func fibonacciGenerator() func() int {
    a, b := 0, 1
    return func() int {
        result := a
        a, b = b, a+b
        return result
    }
}

fib := fibonacciGenerator()
for i := 0; i < 10; i++ {
    fmt.Println(fib())
}
```

#### 5. Замыкания и горутины (Race Conditions)

При использовании замыканий в многопоточном коде (горутинах) необходимо помнить о безопасности разделяемого состояния. Поскольку замыкания захватывают переменные по ссылке, несколько горутин, выполняющих одно и то же замыкание, будут конкурировать за доступ к этим переменным (data race).

```go
// ОПАСНО: race condition
func unsafeCounter() {
    count := 0
    var wg sync.WaitGroup
    
    for i := 0; i < 1000; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            count++ // Несколько горутин изменяют одну переменную!
        }()
    }
    wg.Wait()
    fmt.Println(count) // Результат непредсказуем (обычно меньше 1000)
}
```

Для решения этой проблемы используйте мьютексы (`sync.Mutex`) или атомарные операции (`sync/atomic`).

#### Упражнение 3: Генератор уникальных ID
Реализуйте потокобезопасную функцию `NewIDGenerator(prefix string)`, которая возвращает замыкание. Каждый вызов этого замыкания должен генерировать новую строку вида `prefix-N`, где `N` – последовательно возрастающее число, начиная с 1.

*Требования:*
- Генератор должен быть безопасным для использования из нескольких горутин одновременно (используйте `sync.Mutex` или `sync/atomic`).
- Каждый созданный генератор должен иметь свой независимый счетчик.

Пример использования:
```go
userGen := NewIDGenerator("user")
orderGen := NewIDGenerator("order")

// Параллельные вызовы:
fmt.Println(userGen())  // "user-1"
fmt.Println(orderGen()) // "order-1"
fmt.Println(userGen())  // "user-2"
```
