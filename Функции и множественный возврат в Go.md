#go 

Множественный возврат (multiple return values) является одной из ключевых идиом языка Go. В отличие от многих других языков программирования, где для возврата нескольких значений приходится создавать специальные объекты, кортежи или использовать параметры-выходы, Go позволяет функции возвращать произвольное количество значений естественным образом. Эта особенность лежит в основе главного архитектурного паттерна языка – явной обработки ошибок.

## Основы множественного возврата

Сигнатура функции может указывать несколько типов возвращаемых значений, заключенных в скобки. Вызывающая сторона получает их в виде кортежа и может присвоить отдельным переменным.

```go
func divide(a, b float64) (float64, error) {
	if b == 0 {
		return 0, fmt.Errorf("ошибка: деление на ноль")
	}
	return a / b, nil
}

func main() {
	result, err := divide(10, 2)
	if err != nil {
		fmt.Println("Ошибка:", err)
		return
	}
	fmt.Println("Результат:", result)
}
```

**Правила именования:** По соглашению сообщества Go, последним возвращаемым значением (если их больше одного) обычно является ошибка. Это делает обработку ошибок явной и обязательной – программист физически не может проигнорировать `err`, не присвоив её переменной или явно не отбросив через пустой идентификатор `_`.

### Частичное игнорирование значений

Если какие-то возвращаемые значения не требуются, их можно отбросить с помощью пустого идентификатора `_`:

```go
result, _ := divide(10, 2) // Игнорируем ошибку (антипаттерн!)
```

**Важное предупреждение:** Игнорирование ошибок через `_` считается дурной практикой, которая часто приводит к трудноотлаживаемым багам. Отбрасывание уместно только в тех редких случаях, когда контракт функции гарантирует отсутствие ошибки при данных входных параметрах.

## Паттерн (result, error): философия явной обработки

Идиома `(value, error)` определяет стиль написания кода на Go. Функция возвращает либо корректный результат и `nil` вместо ошибки, либо нулевое значение результата и объект ошибки.

```go
func readFile(path string) ([]byte, error) {
	file, err := os.Open(path)
	if err != nil {
		return nil, err // Возвращаем ошибку выше по стеку
	}
	defer file.Close()

	data, err := io.ReadAll(file)
	if err != nil {
		return nil, err
	}
	return data, nil
}
```

Этот подход имеет ряд преимуществ:

1. **Явность:** Обработка ошибок не спрятана в исключениях – программист видит каждый потенциальный сбой.
2. **Локальность:** Ошибка обрабатывается в том месте, где вызвана функция, что облегчает трассировку.
3. **Семантика:** Нулевое значение результата четко сигнализирует о невалидности данных при наличии ошибки.

### Когда результат и ошибка оба не-nil

Возврат `(value, error)` одновременно ненулевыми значениями возможен, но требует осторожности. Классический пример – функции, которые частично выполнили работу. Например, `io.Reader` может вернуть прочитанные байты **и** ошибку `io.EOF`:

```go
buf := make([]byte, 1024)
n, err := reader.Read(buf)
// err может быть io.EOF, но n > 0 – данные в buf валидны
if n > 0 {
	processData(buf[:n])
}
if err != nil {
	handleError(err)
}
```

**Правило:** Всегда сначала обрабатывайте валидный результат, и только потом проверяйте ошибку.

## Именованные возвращаемые значения

В сигнатуре функции можно задавать имена для возвращаемых значений. Это превращает их в локальные переменные, инициализированные нулевыми значениями своего типа.

```go
func fetchUserInfo(id int) (name string, age int, err error) {
	// name, age, err уже объявлены внутри функции
	if id < 0 {
		err = fmt.Errorf("неверный ID: %d", id)
		return // "Голый" return – возвращает текущие значения name, age, err
	}
	name = "Иван"
	age = 30
	return name, age, nil
}
```

### "Голый" return (Naked Return)

Когда все возвращаемые значения именованы, допускается использование `return` без указания аргументов. Компилятор автоматически подставит текущие значения именованных переменных.

**Когда naked return уместен:**
- В коротких функциях, где переменные уже были установлены в нужные значения.
- В `defer`-блоках, которые модифицируют возвращаемые значения ([см. статью про `defer`](https://github.com/asemyannikov/golit/blob/main/%D0%A3%D0%BF%D1%80%D0%B0%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5%20%D1%80%D0%B5%D1%81%D1%83%D1%80%D1%81%D0%B0%D0%BC%D0%B8%20%D0%B8%20%D0%BE%D1%82%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%BD%D1%8B%D0%B5%20%D0%B2%D1%8B%D0%B7%D0%BE%D0%B2%D1%8B.md).

**Когда naked return опасен:**
- В длинных функциях – читатель не сможет сходу понять, какие значения возвращаются.
- Если логика функции сложна и ветвиста, лучше явно указывать возвращаемые значения для ясности.

```go
// Плохо: в длинной функции неясно, что возвращается
func complexOperation(x int) (result int, err error) {
	// ... 50 строк кода ...
	return // Что именно возвращается?
}
```

## Интерфейс `error` и работа с ошибками

Тип `error` – это встроенный интерфейс с единственным методом `Error() string`. Поскольку это интерфейс, любая структура с таким методом может выступать в роли ошибки.

```go
type error interface {
	Error() string
}
```

### Создание пользовательских ошибок

Существует несколько способов создания ошибок:

```go
// 1. errors.New – простой текст ошибки
err1 := errors.New("что-то пошло не так")

// 2. fmt.Errorf – форматированная ошибка
err2 := fmt.Errorf("неверное значение: %d", value)

// 3. Пользовательская структура с методом Error()
type ValidationError struct {
	Field   string
	Message string
}

func (e ValidationError) Error() string {
	return fmt.Sprintf("поле %s: %s", e.Field, e.Message)
}
```

### Обёртывание ошибок (Error Wrapping) – Go 1.13+

Одной из самых мощных особенностей работы с ошибками в Go является возможность оборачивания (wrapping) ошибок. Это позволяет сохранить контекст возникновения ошибки, сохраняя цепочку вызовов.

```go
func fetchUserFromDB(id int) (*User, error) {
	user, err := db.QueryUser(id)
	if err != nil {
		// %w оборачивает оригинальную ошибку, сохраняя её для последующей проверки
		return nil, fmt.Errorf("ошибка получения пользователя из БД: %w", err)
	}
	return user, nil
}
```

**Ключевое различие:** 
- `%v` – вставляет текст ошибки (теряется тип оригинальной ошибки)
- `%w` – оборачивает ошибку (сохраняет тип и позволяет проверять через `errors.Is` / `errors.As`)

### Проверка типа ошибки: `errors.Is` и `errors.As`

Для корректной работы с обёрнутыми ошибками в Go 1.13 были введены две функции:

```go
// Sentinel errors – предопределенные ошибки
var (
	ErrNotFound     = errors.New("не найдено")
	ErrUnauthorized = errors.New("не авторизован")
)

func processRequest(id int) error {
	user, err := fetchUser(id)
	if err != nil {
		if errors.Is(err, ErrNotFound) {
			return fmt.Errorf("пользователь %d отсутствует: %w", id, err)
		}
		return err
	}
	// ...
}
```

**`errors.Is(err, target)`** – проверяет, содержится ли `target` в цепочке обёрнутых ошибок. Работает аналогично `==`, но рекурсивно разворачивает цепочку.

**`errors.As(err, &target)`** – проверяет, соответствует ли ошибка (или обёрнутая ошибка) определенному типу, и извлекает её:

```go
var valErr ValidationError
if errors.As(err, &valErr) {
	fmt.Printf("Ошибка валидации в поле: %s\n", valErr.Field)
}
```

## Возврат структур vs множественный возврат

Иногда возникает вопрос: когда стоит использовать множественный возврат, а когда возвращать структуру?

### Когда использовать множественный возврат:
- Функция возвращает результат и ошибку.
- Функция возвращает 2-3 семантически разных значения (например, координаты `x, y`).
- Функции стандартной библиотеки (`map`, `channel`, деление и т.д.).

```go
// Хорошо: логически связанные координаты
func getCoordinates() (x, y float64)

// Хорошо: результат + ошибка
func parseJSON(data []byte) (*User, error)
```

### Когда использовать структуру:
- Возвращается больше 3-4 значений.
- Значения тесно связаны и образуют единую сущность.
- В будущем может потребоваться добавить новые поля без изменения сигнатуры.

```go
// Плохо: слишком много значений
func getUserProfile() (name, email, phone, address, bio string, age int, err error)

// Хорошо: структурированные данные
type UserProfile struct {
	Name    string
	Email   string
	Phone   string
	Address string
	Bio     string
	Age     int
}

func getUserProfile() (*UserProfile, error)
```

## Продвинутые паттерны

### Функции-конструкторы с множественным возвратом

Типичный паттерн создания объектов с валидацией:

```go
type Config struct {
	Host string
	Port int
}

func NewConfig(host string, port int) (*Config, error) {
	if port < 1 || port > 65535 {
		return nil, fmt.Errorf("неверный порт: %d", port)
	}
	return &Config{Host: host, Port: port}, nil
}
```

### Возврат функции из функции (Higher-Order Functions)

Go поддерживает возврат функций, что позволяет создавать фабрики и замыкания:

```go
func createLogger(prefix string) func(string) {
	return func(message string) {
		fmt.Printf("[%s] %s\n", prefix, message)
	}
}

func main() {
	infoLogger := createLogger("INFO")
	errorLogger := createLogger("ERROR")

	infoLogger("Запуск приложения")   // [INFO] Запуск приложения
	errorLogger("Критическая ошибка") // [ERROR] Критическая ошибка
}
```

### Вариадивные функции с множественным возвратом

Вариадивные функции могут одновременно принимать `...` аргументов и возвращать несколько значений:

```go
func sumAndAvg(nums ...float64) (sum, avg float64, err error) {
	if len(nums) == 0 {
		return 0, 0, errors.New("пустой набор данных")
	}
	for _, n := range nums {
		sum += n
	}
	avg = sum / float64(len(nums))
	return sum, avg, nil
}
```

## Заключение

Множественный возврат в Go – это не просто синтаксическая возможность, а философский фундамент языка. Он обеспечивает явную обработку ошибок, прозрачность кода и предсказуемость поведения функций. Глубокое понимание паттерна `(value, error)`, умение работать с обёрнутыми ошибками через `errors.Is` и `errors.As`, а также правильное использование именованных возвращаемых значений позволяют создавать надежный и поддерживаемый код, соответствующий лучшим практикам экосистемы Go.
